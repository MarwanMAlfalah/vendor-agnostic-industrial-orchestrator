# Introduction Draft

Industrial software environments are rarely homogeneous. A single operational workflow may need to read machine status from an OPC UA interface, create a maintenance record through a REST service, and validate or invoke a legacy vendor command. This heterogeneity is not only technical. It also introduces governance concerns: some steps are read-only and can be executed automatically, some require explicit approval, some must be blocked, and some should safe-abort when a mapping or payload is invalid. A useful orchestration system for such settings must therefore do more than connect APIs. It must preserve policy intent across planning, capability matching, governance evaluation, and execution.

Recent advances in agentic workflow orchestration create an opportunity to revisit this problem. Agents can decompose goals, select capabilities, and coordinate execution paths, but unconstrained execution is not appropriate for industrial settings. In governed workflows, raw task success can be misleading: an action may succeed technically while violating an approval gate or bypassing a safety-oriented block. This paper therefore treats policy compliance, unsafe execution, approval bypass, invalid mapping containment, trace completeness, and checkpoint reopen/resume as first-class evaluation dimensions.

We present a deterministic prototype for vendor-agnostic, governance-aware industrial orchestration. The prototype uses mock OPC UA, REST, and legacy adapters, a capability registry, a governance layer, and a governance-aware execution path. A reference runtime, `reference_v1`, implements deterministic planning, capability matching, governance evaluation, blocking, safe aborts, and approval-required decision recording (without a workflow-wide pause). An optional `langgraph_runtime` preserves the same governed execution semantics while adding controlled post-approval continuation, graph-native interrupt/resume, checkpoint persistence, and richer trace markers. Three baselines remove governance or architectural protections to provide comparative evidence.

The paper makes five contributions. First, it proposes a reference architecture for governance-aware vendor-agnostic orchestration. Second, it implements the architecture as a deterministic research prototype with heterogeneous mock adapters. Third, it compares the reference runtime with governance-ablated baselines and a LangGraph runtime variant. Fourth, it introduces a scaled deterministic scenario generator, including a 240-scenario journal profile and a 500-scenario extended profile. Fifth, it applies runtime-specific expectation alignment so that runtimes are evaluated against capabilities they actually support, while original scenario labels and negative results remain visible.

The empirical results support the feasibility of policy-centric orchestration in deterministic prototype settings. In canonical governance cases, the reference runtime achieves policy compliance of 1.0 and unsafe execution of 0.0. In the aligned journal profile, both `reference_v1` and `langgraph_runtime` achieve aligned policy compliance of 1.0, final outcome accuracy of 1.0, unsafe execution of 0.0, and trace completeness of 1.0. Baselines remain intentionally weak: direct execution without governance and execution without policy filtering both show conditional unsafe execution of 1.0 in the aligned journal results. These findings support a cautious claim: governance-aware orchestration can be evaluated reproducibly and can prevent unsafe execution in controlled deterministic scenarios. They do not establish production safety, live PLC readiness, or certified industrial deployment.
