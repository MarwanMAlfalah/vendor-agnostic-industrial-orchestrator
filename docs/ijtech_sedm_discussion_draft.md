# Discussion Draft

The results show why raw task success is an incomplete metric for industrial orchestration. A baseline can execute many adapter calls and still violate the intended governance policy. In the canonical comparison, Baseline B reaches full execution coverage but has unsafe execution of 1.0 and policy compliance of only 0.25. In the aligned journal profile, direct execution without governance and execution without policy filtering both show conditional unsafe execution of 1.0. These results support a policy-centric interpretation of orchestration quality.

Policy compliance, unsafe execution, approval bypass, and invalid mapping containment are therefore more informative than success rate alone. The reference runtime records approval requirements and enforces blocks/safe aborts; LangGraph additionally interrupts/resumes for approval. This distinction matters in industrial contexts because the absence of execution can be the correct outcome when an action is blocked, approval is missing, or a capability mapping is invalid.

The LangGraph runtime adds value at the runtime level. It preserves deterministic governance behavior while supporting approval interrupt/resume, controlled post-approval continuation, checkpoint persistence, and graph-native trace markers. This value is not simply higher task success. It is the ability to represent and recover governed workflow state around approval checkpoints, which the simpler `reference_v1` path intentionally does not support.

Runtime-specific expectation alignment is methodologically fair because the evaluated runtimes do not claim identical capabilities. The reference runtime is a policy-correct non-continuation runtime; it should not be penalized for failing to perform controlled continuation that it does not implement. The LangGraph runtime, by contrast, should be evaluated for continuation behavior when valid approval and revalidation are present. This alignment is not metric manipulation because original labels remain visible, all rules are documented, and unsafe execution or approval bypass remains non-compliant.

The evaluation remains limited. Scenarios are synthetic and deterministic, adapters are mock implementations, and latency is measured locally. The evidence supports feasibility, architecture, methodology, and runtime semantics. It does not establish certified safety, production deployment readiness, live PLC integration, or generalization to all industrial environments.
