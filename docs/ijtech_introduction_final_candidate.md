# IJTech Introduction Final Candidate

Industrial software environments are rarely homogeneous. A single operational workflow may need to read machine status from an OPC UA interface, create a maintenance record through a REST service, and validate or invoke a legacy vendor command (Author, year). This heterogeneity is not only technical. It also introduces governance concerns: some steps are read-only and can be executed automatically, some require explicit approval, some must be blocked, and some should safe-abort when a mapping or payload is invalid (Author, year). A useful orchestration system for such settings must therefore do more than connect APIs. It must preserve policy intent across planning, capability matching, governance evaluation, and execution.

Recent advances in agentic and graph-based workflow orchestration create an opportunity to revisit this problem (Author, year). Agents and workflow graphs can decompose goals, select capabilities, and coordinate execution paths, but unconstrained execution is not appropriate for industrial settings (Author, year). In governed workflows, raw task success can be misleading: an action may succeed technically while violating an approval gate or bypassing a safety-oriented block. This paper therefore treats policy compliance, unsafe execution, approval bypass, invalid mapping containment, trace completeness, and checkpoint reopen/resume as first-class evaluation dimensions.

This paper presents a deterministic prototype for vendor-agnostic, governance-aware industrial orchestration. The prototype uses mock OPC UA, REST, and legacy adapters, a capability registry, a governance layer, and governance-aware execution paths. The reference runtime, `reference_v1`, implements deterministic planning, capability matching, governance evaluation, blocking, safe aborts, trace recording, and approval-required decision recording (without a workflow-wide pause). The optional `langgraph_runtime` preserves the same governed execution semantics while adding controlled post-approval continuation, graph-native interrupt/resume behavior, checkpoint persistence, and richer trace markers (Author, year). Three deterministic baselines remove governance or architectural protections to provide comparative evidence.

The empirical evaluation is journal-oriented. It includes a 240-scenario journal profile and a 500-scenario extended profile generated from deterministic factors: workflow length, governance pattern, adapter mix, approval condition, and failure or containment condition. The results are reported using both original global expected outcomes and runtime-specific aligned expected outcomes. This distinction matters because `reference_v1` is a policy-correct non-continuation runtime, whereas `langgraph_runtime` supports controlled continuation after approval validation and revalidation. Alignment is documented explicitly, original labels remain visible, and unsafe execution or approval bypass remains non-compliant for every runtime.

The paper makes the following contributions:

1. It proposes a governance-aware architecture for vendor-agnostic orchestration across heterogeneous industrial-style interfaces.
2. It implements the architecture as a deterministic research prototype using mock OPC UA, REST, and legacy adapters.
3. It evaluates governance-aware runtimes against deterministic baselines that remove governance enforcement, planner/matcher separation, or policy filtering.
4. It introduces a scaled deterministic scenario benchmark with a 240-scenario journal profile and a 500-scenario extended profile.
5. It reports both original and runtime-aligned metrics, including policy compliance, unsafe execution, approval bypass, invalid mapping containment, trace completeness, latency, and supported-versus-stress scope behavior.
6. It provides prototype-level evidence for LangGraph approval continuation and local checkpoint reopen/resume, while treating LangSmith only as observability evidence.

The results support a cautious conclusion: governance-aware orchestration can be evaluated reproducibly and can prevent unsafe execution in controlled deterministic scenarios. They do not establish certified safety, production deployment readiness, live PLC integration, regulatory compliance, or generalization to all industrial environments.
